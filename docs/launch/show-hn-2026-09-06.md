**Title:** Show HN: DashClaw – a policy and approval layer so coding agents can run unattended

I wanted my coding agents to run unattended for hours without handing them unconditional control over my machine, my repos, production data, or money. So I built DashClaw.

It's an open source policy and approval layer that sits between an agent deciding to act and the action actually running.

The part I care about isn't blocking `rm -rf`. It's that a policy can say: let this agent edit code freely, warn on unusual commands, pause before production changes or anything that talks to a customer, require approval before touching customer data, and require an exact-amount approval before spending real money. Policies compose and the most restrictive decision wins:

`allow < warn < allow_contained < require_approval < block`

The other thing I'm trying to solve is alert fatigue. Approve and deny decisions feed a calibration loop that proposes better boundaries instead of just piling up more rules. I learned why that matters the hard way. In June I got annoyed enough at false interruptions that I turned off all my policies for 18 days. That failure is now part of the design: an interruption has to earn its cost.

The stranger part is how it gets built. Claude Code maintains the project day to day under a constitution it can't edit. It picks and implements roadmap work, writes the tests and docs, and keeps the calibration corpus current. And DashClaw governs that maintainer. The agent can't approve itself, can't loosen policy to unblock itself, and credential-gated actions still come to me. So the project is basically a running experiment in whether an AI can maintain the system that constrains its own autonomy. It's been dogfooded that way the whole time, including catching the maintainer trying actions that violated policy.

MIT licensed, self-hostable, no account:

`npx dashclaw up`

https://github.com/ucsandman/DashClaw

I'm most interested in criticism of two things: the policy model, and the self-governing maintainer experiment.
